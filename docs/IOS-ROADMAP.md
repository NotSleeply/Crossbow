# Crossbow iOS 开发路线

关联设计 issue #124、设计 PR #126；架构及交互约定见 [IOS-MVP.md](IOS-MVP.md)。本路线是后续实施和验收计划，不代表真实 VPN 已实现。

用户目标：已有付费个人开发者账号，先在 iPhone 17 标准版 / iOS 27.0.1 上自用，再进入 TestFlight；为未来 iPhone duo 等窗口形态保留适配空间。

## 路线与时间口径

```mermaid
flowchart LR
  M0[M0 工程与签名] --> M1[M1 最小真机隧道]
  M1 --> M2[M2 订阅与共享核心]
  M2 --> M3[M3 日用界面]
  M3 --> M4[M4 稳定性与设备适配]
  M4 --> M5[M5 TestFlight]
```

初步按 **19–29 个有效开发工作日，约 4–6 周开发量** 分配，不含等待账号/签名处理、用户真机验收和 Apple 审核。它是规划估算，不是发布日期承诺；M1 完成后按实际 libbox 集成、依赖编译和设备资源结果重新估算。

| 里程碑 | 初步开发量 | 可交付结果 | 是否需要用户真机配合 |
|---|---:|---|---|
| M0 工程与签名 | 1–2 日 | 可安装的 App + 已嵌入的扩展，构建与身份配置明确 | 登录团队、连接并信任 iPhone |
| M1 最小真机隧道 | 3–5 日 | 第一个能连接/断开并实际联网的验证包 | 首次 VPN 授权、浏览器与网络切换验收 |
| M2 订阅与共享核心 | 4–6 日 | 导入自己的配置、转换校验、保存和安全切换 | 导入本机可用订阅并核对常用协议 |
| M3 日用界面 | 5–7 日 | 四 Tab、选节点/测速、速率、日志诊断和统一通知 | 日常操作与失败恢复验收 |
| M4 稳定性与适配 | 4–6 日 | 达到持续日用门槛的候选包 | 锁屏/后台、升级、蜂窝及 Wi-Fi 场景 |
| M5 TestFlight | 2–3 日工程准备 | 经签名归档、内部测试并具备外测提交材料的包 | 分发资料、账号及审核操作 |

M0/M1 对应 MVP 设计中的阶段 A；M2 对应 B；M3/M4 对应 C；M5 对应 D。先验证最小隧道；界面草图可独立迭代，但完整功能依赖真实数据通道。

## M0 · 工程与签名

目标：消除「工程能打开，但扩展没有正确打包或没有权限」的不确定性。

开发范围：

- 修正 XcodeGen target 关系、扩展嵌入、入口类和 Info.plist；明确 App、扩展、App Group 的唯一标识。
- 配置本地 Team ID 与签名入口；账号、证书私钥不进仓库，CI 签名另用受控 secrets。
- 锁定 libbox 源码版本、工具链、构建标志、校验值和许可证记录；明确 iPhone/模拟器需要的切片。不能假设任意 Release 都提供现成 XCFramework。
- 增加可重复的工程生成及无签名构建命令。先保留最小连接状态页，不把占位页面当成功连接。
- 核验本机 Xcode、设备系统版本与最终最低部署版本。当前建议 iOS 17 起，依赖验证后锁定。

验收门槛：App 与扩展均能编译；签名后的包可装到用户 iPhone；归档能检查到正确扩展、ID 和 entitlement。能力无法签发或签名失败要明确诊断，不能用模拟器通过替代真机结果。

PR 拆分：`build(ios): add reproducible app and tunnel targets`；必要时将依赖构建单独成 PR，避免把 Framework 二进制和凭据直接塞进仓库。

## M1 · 最小真机隧道

目标：交付第一个真实联网包，以一份本地、已知可用的 sing-box 测试配置起步。

开发范围：

- 实现 `TunnelManager` 和 PacketTunnel/libbox 适配；连接、取消、断开均串行，状态监听以系统和扩展实际状态为准。
- 设置路由、DNS、IPv4/IPv6 与平台接口；使用 App Group 中受保护的配置快照，不额外暴露局域网控制接口。
- 配置验证与启动失败给出有限、脱敏日志；保留基本顶部通知，不等完整通知 UI 才处理错误。
- 主 App 进入后台或退出前台不成为转发依赖；错误清理、停止回调和重新连接可重复。
- 记录真实设备上的内存、CPU、初步耗电和后台行为，尽早验证 libbox 资源可行性。

用户验收：首次授权允许/拒绝；浏览器访问 YouTube、X、Google、GitHub；连接/断开/重连；锁屏及 Wi-Fi/蜂窝切换。站点 HTTP 受限要单独解释，不能把它等同于隧道死亡。

通过条件：不是只出现 VPN 图标，而是有实际流量；断开后不残留异常网络状态。基础生命周期失败时先解决，不用更多页面掩盖问题。

PR 拆分：`feat(ios): connect a minimal packet tunnel`，随后按真实反馈提交生命周期修复。M1 结束后更新后续工期和风险。

## M2 · 订阅与共享核心

目标：从固定测试配置升级为用户自己的订阅，保持桌面共享逻辑的行为。

开发范围：

- 增加独立 UniFFI 包装层，只暴露配置相关小接口；共享 crate 的移动特性关闭 JS 覆写，保留桌面默认能力。
- 支持用户主动输入订阅 URL、文件导入、本地 sing-box JSON 与 Clash YAML 的明确可转换子集。
- 优先验证用户常用 Hy2、VLESS，再覆盖已有转换器支持的协议；协议名相同也要验证传输、TLS 和参数组合。
- 对无法支持的规则/协议报具体原因，特别是普通 iOS 环境的进程规则；不静默删规则、不宣称全量 Clash 兼容。
- Keychain 处理凭据；App Group 原子快照带配置版本与摘要。切换/更新失败保留最近可用配置，扩展不改写主 App Store。
- 从扩展提供受限、版本化的状态/节点控制通道；请求 ID、超时和迟到响应处理一起实现。

通过条件：真实订阅导入 → 校验 → 连接 → 更新/切换可复测；配置错误不损坏旧配置；日志与导出不泄露订阅 token；Rust 单测、iOS/模拟器构建及相关桌面回归通过。

PR 拆分：`feat(core): expose mobile configuration bindings`、`feat(ios): import and activate validated profiles`。共享层改动先过现有桌面测试，再由移动壳消费。

## M3 · 日用界面

目标：以 M1/M2 的真实数据替换草图模拟状态，形成完整使用闭环。

| 页面/能力 | 实现内容 | 重点验收 |
|---|---|---|
| 首页 | 单一连接入口、实际状态、配置、节点、上下行速率、规则/全局/直连 | 等待授权或失败时不提前显示已连接；重开同步实际状态 |
| 代理 | 自动选择、地区分组、搜索、单节点/批量延迟测试 | 逐项 loading；0/超时不显示绿块；点选保留列表 |
| 配置 | 导入、更新、切换、来源和更新时间、兼容诊断 | 快速切换不回写旧结果；失败保留可用配置 |
| 设置 | 应用/内核版本、明暗/跟随系统、日志、诊断、通知历史 | 错误可以展开脱敏详情；统一通知 operationId |
| 站点检查 | 经当前隧道/配置的站点连通性、HTTP 状态与耗时 | 与节点延迟、隧道连接状态分别展示 |

自动选择含义是最低可用测试延迟，不是最高下载带宽；没有可用结果时明确提示。速率、日志和连接数据低频/按需同步，主 App 在后台不保持高频轮询。

通过条件：普通用户从干净安装到导入/连接/选节点/诊断均有清晰路径；加载、空状态、无网络、权限拒绝、配置不兼容和重试均可操作。

PR 拆分：按「主导航与首页」「节点列表与测速」「配置与设置」「统一通知和诊断」分别提交，避免单个巨大界面 PR。

## M4 · 稳定性与设备适配

目标：从「能用」达到持续日用与升级可恢复。

- 测试前后台、锁屏、低电量、断网、飞行模式、Wi-Fi/蜂窝切换、系统中手动断开、设备重启后的恢复路径；On-Demand 暂不启用。
- 多轮快速连接/取消、换配置和测速，验证旧异步回调不能覆盖新状态，停止后没有假速率。
- 测试 IPv6/NAT64、DNS 失败、远程规则集首次加载和离线缓存；需要下载的配置数据失败时有界限和清楚提示。
- 限制日志、连接数据和缓存的大小，记录前后台设备内存/CPU/电量；测出基线后制定回归阈值，不虚构通用扩展内存额度。
- iPhone 17 / iOS 27.0.1 为首轮实机；窄窗口、大字体、VoiceOver、明暗、减少动态效果、横屏用模拟器/可用设备覆盖。
- 按可用宽度、安全区和窗口变化适配；iPhone duo 等未来设备的实际规格与 SDK 未确认前不硬编码，不承诺当前已完成专机适配。设备公开后补专项用例。
- 测试升级安装、配置 schema 迁移、旧快照回退、通知/诊断导出脱敏。

通过条件：无阻断联网、假连接、配置丢失、凭据泄露或可稳定复现的启停失败；候选包由用户持续使用反馈后才能进入分发阶段。

PR 拆分：按根因提交稳定性修复；适配与资源优化可独立评审，不借此重写桌面端。

## M5 · TestFlight

目标：先完成受控测试，再申请外部测试。审核和账号处理不计入上述开发量。

- 固定版本/build 规则、Release Archive、签名及上传流程；PR 构建默认不访问签名私钥。
- 准备 App Store Connect 记录、隐私政策、数据声明、出口合规说明、测试说明与反馈入口。
- 对固定版本 libbox、Rust 及依赖记录许可证与对应源码/构建材料，核对预定分发条件。
- 个人账号的真机开发权限，不等于 VPN 公开分发资格；外部 TestFlight 按 Beta App Review 流程提交。根据 Apple 对 Crossbow 客户端用途的答复处理组织账号和分发区域问题，不提前保证审核通过。
- 先内部测试，再分批邀请外部测试者；测试问题形成 issue，按严重程度修复和重新归档。

通过条件：Account Holder 完成资料与资格确认；受控测试安装、启动、更新和联网通过；向外部提供构建前完成相应审核流程。

PR 拆分：`ci(ios): archive and distribute beta builds` 与发布资料文档分别提交。CI 上传凭据在启用时配置，不进入代码或聊天记录。

## 首版之后

| 顺序 | 功能 | 开始前提 |
|---|---|---|
| 1 | 快捷指令、Widget、可选 On-Demand | 启停与网络切换稳定，能尊重用户在系统里的手动断开 |
| 2 | iCloud 同步 | 本地 schema/凭据边界稳定，具备冲突解决与用户选择 |
| 3 | 更多协议/规则与高级覆写 | 有具体兼容需求和测试样例；先确认平台能力及分发约束 |
| 4 | 丰富连接统计、规则命中与诊断 | 隧道资源预算和隐私边界允许 |
| 5 | iPhone duo 等新形态专项优化 | 有公开 SDK、模拟器或真实设备进行验收 |

## 开发与验收分工

- 开发侧：代码、自动化检查、无签名构建、配置与状态机测试、模拟器布局、可安装测试包及每阶段简短验收步骤。
- 用户侧：账号登录/系统授权、真实订阅在本机导入、iPhone 真机联网/后台/外观验收、TestFlight 账号与提交资料确认。
- 每个实施任务开始前建对应 issue 并认领；每个 PR 关联实际问题。这里列的是规划，不预先替其他会话认领实现范围。
- 每个阶段交付一个明确可测试的结果；编译通过、模拟数据和真实联网分别记录。用户验收失败先修当前门槛，不把阶段标记为完成。
- 现有设计 PR 不代表允许自动合并后续实现 PR；继续遵守 AGENTS.md 的合并确认要求。
